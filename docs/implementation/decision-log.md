| D-013 | Workspace, membership and invitation ids are generated by PostgreSQL; better-auth generates the others. Workspace roles come from `WORKSPACE_ROLES`.                                                                                                                                                                                                                                                              | better-auth's own ids are not UUIDs.                                                                                   |
| D-014 | A text id is the base64url of the JSON array `[source, ...path]`.                                                                                                                                                                                                                                                                                                                                                 | Deterministic, safe in a URL, and `["a.b"]` and `["a","b"]` stay two ids.                                              |
| D-015 | The catalog reads git through one `GitReader` seam: a local reader (`git cat-file --batch` in `GLOT_GIT_ROOT/<repository>`) and a GitHub reader (`git/ref` for the head, `contents` as raw for files, token optional). The local reader needs the `git` binary in the image.                                                                                                                                      | The suite and self-hosters use the local clone; hosted use GitHub.                                                     |
| D-016 | A catalog is cached per project, commit and source settings. The branch head is re-read at most every 60 seconds; `projects.sync` re-reads it now.                                                                                                                                                                                                                                                                | Bounded GitHub calls, and a commit can be shown on demand.                                                             |
| D-017 | A text's state is missing, then needs a fix, then reviewed, then to check. Approvals come from pending PostgreSQL rows and released `.glot/reviews/<language>.jsonl` lines `{key, sourceHash, targetHash, reviewedBy}`; a malformed line counts for nothing.                                                                                                                                                      | A failed check always wins, and a damaged line can never approve.                                                      |
| D-018 | Checks: a syntax error stops the other checks of that text; placeholders are compared as sets across all plural forms; plural forms must be as many as the source's; HTML tags are compared by name and opening or closing, not attributes; words to avoid match whole words, in any case, in plain text.                                                                                                         | Fewest false alarms while still catching what breaks an app.                                                           |
| D-019 | `project_source` holds the sources of a project and `project_app_source` the sources each app shows. Until the key log exists, `where` is the source name, `shownIn` the apps showing the source, and texts come in source name then file order.                                                                                                                                                                  | The contract fields stay real without inventing page counts.                                                           |
| D-020 | `hashText` lives in `@glot/utils/hash`, shared by the server, the seed and the release.                                                                                                                                                                                                                                                                                                                           | One definition of what an approval is bound to.                                                                        |
| D-021 | The first administrator is created by a better-auth plugin in `@glot/auth` (`/api/auth/setup/status`, `/api/auth/setup/complete`, and a server-only `issueSetupLink`). The setup link carries a random token kept hashed in the `verification` table and consumed atomically; setup is open only while no user exists. The administrator becomes owner of the new workspace and is signed in by the same request. | Uses better-auth's session cookie and storage, single use is enforced by the database, and no schema change is needed. |
| D-022 | The server runs its migrations on start when `MIGRATIONS_FOLDER` is set (the image sets it), then prints the setup link, in one Nitro plugin (Nitro does not await plugins in order). One server instance runs per database.                                                                                                                                                                                      | A container needs no separate migration step or tooling.                                                               |
| D-023 | Sign-in emails are sent through SMTP when `SMTP_URL` and `MAIL_FROM` are both set; SMTP wins over the development printing of links. The drizzle adapter of better-auth runs multi-write operations in transactions (`transaction: true`).                                                                                                                                                                        | Self-hosters bring their own mail account; the setup and invitations never leave half-written people.                  |
| D-024 | One CI workflow (`.github/workflows/ci.yml`) runs `bun run check`, `bun run lint:rules:test` and `bun run test` against a PostgreSQL 18 service on pull requests and on `main`, cancels superseded runs per ref, and pins every action by commit.                                                                                                                                                                 | Bounded CI cost, reproducible runs.                                                                                    |
