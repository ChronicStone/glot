# In-app editing: research and decisions

Date: 2026-11-27. Scope: `@glot/nuxt`, the module that lets members of a project edit its texts inside the running Nuxt 3 and 4 apps (vue-i18n 11, `@nuxtjs/i18n`). The slice is [in-app editing](../implementation/slices/in-app-editing.md); the requirements come from the pre-spec (§3, §8.2, §13) and its measured loops.

Each claim is marked **measured** (run here or in the pre-spec loops), **documented** (a vendor's own docs, linked at the end) or **inferred**.

## What has to hold

- Production builds that do not enable the module carry no Glot byte. Builds that enable it (integration, UAT) cost a non-member nothing visible and almost nothing downloaded.
- A member signs in through Glot, in a popup, and gets a short-lived token for one project. A non-member never sees a widget.
- The member sees the texts of the current page in the drawer "On this page", grouped Needs a fix, To check, then the rest, with their states from Glot, and each text with its key (D-041).
- Clicking a text in the page or in the drawer opens an editor. The draft shows in the page for its author only and is saved to Glot as a draft.
- The widget looks exactly like the mockup states `#widget` and `#widget-drawer`, built from the app's own stylesheet (`@glot/ui/theme.css`, `@glot/ui/glot.css`).

Three families come out of it:

1. **Change the string** (Tolgee, locize, Sanity, Phrase, Crowdin). Exact mapping wherever the string lands, including attributes and `document.title`. The price is documented by the vendors themselves: Sanity warns that encoded strings break comparisons, URL building, date parsing and length checks, and ships `stegaClean()`; Tolgee notes the characters "are not empty, only zero width" and break other tools; Crowdin and Phrase show raw ids or keys when the swap fails.
2. **Mark the element** (Storyblok, Lokalise, Builder). Clean strings, but every call site has to carry the attribute, through an SDK component or by hand.
3. **Edit elsewhere** (Fink, Sherlock). No in-context mapping at all.

## Decisions

### 1. Mapping a text in the page to its key: a key log over Vue's own tree, no markers

- **How.** The module composes the app's post-translation handler (calls the previous one, records its result, returns it unchanged). Each call records `key → text` under `getCurrentInstance()`, or under the page when no component renders (toasts from handlers, `useHead`). To resolve, the widget walks the vnode tree from `app._instance` (component `subTree`, Suspense branch, Teleport children, fragments) and maps each element and text node to the component that rendered it. A node resolves through its owner, then the owner's ancestors (slots), comparing text: exact, then contained (`{{ t('a') }}: {{ n }}`), then a truncated prefix. Same text from two keys in the same component gives a chooser that shows both keys.
- **Attributes.** `placeholder`, `title`, `aria-label`, `alt` and `value` come from the element vnode's props and are matched the same way, so they are clickable on their element.
- **`v-html`.** The element's `innerHTML` prop is compared after removing tags.
- **Plurals and linked messages.** The handler sees the chosen form and the final text; the editor opens the whole message, every form, with `@:key` as a chip.
- **`rt()`.** Its "key" is a message source: when it is not a key of the locale, the source is looked up among the locale's messages and every key holding it is offered.
- **Strings captured before the handler.** The handler is installed in the plugin, before the app mounts, whenever a member's token is in the browser. A member who signs in later gets one forced re-render (`locale` set to itself through a microtask toggle); strings frozen in setup state fall back to the catalog lookup above.
- **Not clickable.** Keys logged on this page that no node renders (`document.title`, an `aria-live` region, a closed menu) are listed in the drawer under "Not clickable".
- **SSR.** Nothing changes in any string, on the server or the client: no hydration mismatch, no state contamination.
- **Performance.** One `WeakMap` lookup and one `Map` write per `t()` call while a member is signed in; nothing for others. The tree walk runs only while the drawer is open, after a DOM mutation, coalesced to one per animation frame; box positions are read in one batch per frame.
- **Shared texts.** "Statut" × 37 only collides when two keys with the same words render in one component; the chooser shows the keys.

Rejected:

| Option                                              | Why not                                                                                                                                                                                          |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Zero-width markers (Tolgee, locize, Sanity stega)   | Hydration mismatch on SSR pages; markers leak into state, comparisons, URLs, lengths, payloads (Sanity's own caveat list); `<i18n-t>` VNodes; strings computed before edit mode carry no marker. |
| Key decorators or pseudo-language (Phrase, Crowdin) | A separate mode or build that shows keys or ids instead of the words people review; layout and "fits the line" become meaningless.                                                               |
| `data-*` attributes from a compiler transform       | Covers only literal calls in templates (not the 258 template keys, script-side computed strings, props passed down to library components); changes the DOM of every enabled build.               |
| `__vueParentComponent` or devtools hooks            | Dev or `__VUE_PROD_DEVTOOLS__` builds only (measured), and the flag would change the UAT build.                                                                                                  |
| Source maps                                         | Locate a component file, not a key.                                                                                                                                                              |

Residual risk: `app._instance` and vnode fields are Vue internals that devtools also rely on; a Vue minor that changes them breaks resolution, not the app. The resolver is covered by the playground test on every Vue bump.

### 2. Edit mode

- **Activation.** The pill shows only in a browser that holds a token or a past sign-in for this project, or when the URL carries `?glot`. Opening the drawer is edit mode: texts show their state on the page and clicking a text edits it instead of acting (the click, its `pointerdown` and `mousedown` are swallowed only for texts that resolve). Alt + click edits a text with the drawer closed. `Esc` closes the editor, then the drawer.
- **Outlines.** Drawn as boxes in the widget's own layer from `Range.getClientRects()` (text nodes) or `getBoundingClientRect()` (attributes), position fixed. The host's DOM and styles are never touched, so layouts cannot break. The rects are viewport coordinates after transforms, sticky and fixed positioning; they are re-read on scroll (capture, passive), resize and mutations, once per frame. Iframes and closed shadow roots are out of reach; open shadow roots are walked.
- **States on the page.** As in the mockup: To check dashed blue with `?`, Needs a fix solid red with `!`, the edited text solid blue. Reviewed texts get an outline only on hover.
- **Editing surface.** A popover anchored under the text (above when there is no room, clamped to the viewport, following scroll), never inline in the host DOM: inline editing fights the host's components and Vue's reconciliation. It shows the language, the key, the state, the value with placeholders as chips (typed `{name}` becomes a chip, a chip is deleted whole), the check failures in words, and Save draft and Send for review.
- **Live preview.** Every change is merged into the running locale (`mergeLocaleMessage`) for this browser only, after hydration, and re-applied after each locale load. The base value of each touched key is kept: closing without saving restores it; a key that had no value is removed by rebuilding the locale without it (`setLocaleMessage`).
- **Plurals and HTML.** Plural messages edit form by form, each labelled with the language's numbers (`Intl.PluralRules`, pl 1 · 2–4 · 5+). HTML tags become paired chips with locked attributes, as in the app's editor.
- **Languages.** The drawer header switches the page's locale between the app's locales (segmented control up to four, a select beyond); the language edited is the page's language, and only the languages the member changes are editable, the others read only.
- **Drawer.** "On this page" lists what this page rendered since it loaded: Needs a fix, To check, Reviewed (folded into one line), Not clickable. The strip on top counts them and jumps to a group. Every row shows the text, its key and the reason. The footer names the person and the environment and opens Glot.
- **Phone.** At 375 px the drawer becomes a bottom sheet over the page and the editor a full-width sheet.

### 3. Isolation

- **Styles.** One open shadow root holds the whole widget. Its stylesheet is `@glot/ui/theme.css` + `@glot/ui/glot.css` compiled at module setup, with `:root` → `:host`, `html.dark` → `:host(.dark)` and `.dark ` → `:host(.dark) ` rewritten, Tailwind's preflight for `:host`, and `:host { all: initial }` so no inherited host style comes in. Nothing goes out: the only document-level CSS is the `@property` rules (which shadow roots cannot declare) and `@font-face` with Glot-prefixed family names (`Glot Inter`, `Glot Geist Mono`), so a host's own Inter is never replaced. Fonts are served from the app's origin under `/_glot/`.
- **Theme.** The widget follows the system appearance (`prefers-color-scheme`), not the host's.
- **Stacking.** The host element is a manual popover shown in the top layer, above any `z-index`, with `z-index: 2147483647` as a fallback where the popover API is missing. A host `<dialog>` opened with `showModal()` makes the rest of the page inert, the widget included: a known limit, none of the four apps uses native modal dialogs today (Naive and Nuxt UI overlays are `div`s).
- **Focus and outside clicks.** Host focus traps (Reka `FocusScope`, focus-trap) and dismissable layers listen on `document`. A listener on `window` in the capture phase, the first stop of every event, stops `focusin`, `pointerdown`, `mousedown` and `touchstart` that come from inside the widget, and `focusout` whose `relatedTarget` is the widget, so a host modal neither steals the focus back nor closes when the member types in the editor. `keydown`, `keyup` and `click` are stopped at the widget's host element after its own handlers ran, so host shortcuts never fire while typing.

- **Controls: Glot's classes, not Nuxt UI components.** Weighed because the app is built on Nuxt UI. Measured in `@nuxt/ui` 4.13.1 and `reka-ui` 2.11.0: every Nuxt UI component imports its theme from `#build/ui/<component>` and `useAppConfig` from `#imports`, which in a Nuxt host resolve to the host's own build. A host without Nuxt UI has neither unless Nuxt UI's templates are registered in it (its `app.config.ui` then joins the host's config). A host with Nuxt UI, as the Agorastore apps are becoming, hands the widget its own version and theme. Reka keeps its dismissable-layer stack at module level (`context.layersRoot`), so one deduped `reka-ui` makes the widget's popovers members of the host's layer and focus stack. Either way the widget stops being isolated. The widget therefore renders its few controls (buttons, segmented controls, a native select beyond four languages, the editor popover, positioned by hand against a text's rect rather than a trigger) with the classes of `@glot/ui/glot.css`. These are the same classes the app's own screens use, on the same `--glot-control-h` scale.

### 4. Auth and security

- **Sign in.** The pill opens `GLOT_URL/widget/sign-in?origin=…&project=…&state=…` in a popup. That Glot page signs the person in if needed (email link: the popup waits and continues once the link is opened in any tab; Google: a redirect inside the popup), then asks the server for a widget token for the opener's origin and the project's repository. It posts the result to `window.opener` with `targetOrigin` set to that origin, and closes. The widget accepts only a message whose `origin` is Glot's, whose `source` is its popup and whose `state` matches the one it generated.
- **Token.** Minted by `widget.token`, people-only (an API key can never mint one): an HMAC-signed payload `{session, user, project, origin, expires}`, valid one hour, refreshed by the widget while the Glot session lives. Every request re-checks the signature, the expiry, that the request's `Origin` is the token's, that the Glot session still exists (signing out of Glot signs the widget out), and the person's membership and rights through the existing services.
- **Scope.** The token is accepted only on `/widget/rpc`, which serves the texts of its one project and the person's own drafts (`texts.byKeys`, `texts.get`, `drafts.save`, `drafts.send`, `drafts.withdraw`, `widget.token`). It never approves, releases or manages people.
- **Origins and CORS.** The Glot server lists the apps' origins in `WIDGET_ORIGINS`; `/widget/rpc` answers CORS for those only, without credentials (the token is a header, so there is no CSRF on it). `widget.token` refuses any other origin. The sign-in page refuses to be framed.
- **Who.** Only active members of the project's workspace. Members whose access has an end date (externals, pre-spec §3) are refused on origins listed in `WIDGET_PRODUCTION_ORIGINS`.
- **Storage.** The token lives in the host origin's `localStorage` so the pill survives reloads and tabs; a script injected in the host could read it, which is why it is short-lived, origin-bound, project-bound and limited to drafting. A non-secret flag remembers that this browser signed in before, so the pill can offer to sign in again once the token is gone.
- **Drafts stay private.** Drafts are fetched with the author's token and merged in the author's tab only; texts sent for review by others are shown in the drawer but never applied to the page.
- **Host CSP.** `connect-src` adds the Glot server; scripts, styles (constructed in JavaScript) and fonts come from the app's own origin.

### 5. Data

- **One call per page.** A new `texts.byKeys` procedure (`POST /projects/{projectId}/texts/by-keys`) takes up to 1,000 keys as the app calls them (`marketplace.itemCard.outbid`) and returns those texts with every language, state, failures and the caller's draft. It reuses `TextsService.all`, so the catalog cache, approvals, glossary failures and draft visibility stay owned in one place. It is also useful to services and agents, so it is a public text procedure, not a widget one. A dotted key matches every text whose path joins to it (`["a.b"]` and `["a", "b"]` both), and the widget offers a choice when two do.
- **No schema change.** Allowed origins are configuration; the token is signed, not stored.
- **Writes.** Saving, sending and withdrawing use the existing drafts procedures; rights per language are the server's (`RightsService.access`), and the widget learns the languages it may change from `widget.token`.
- **Cache and network.** Texts are fetched when the drawer opens and when new keys appear (batched each second), and re-read on focus. A save that fails keeps the draft in the tab and retries; the drawer says Glot cannot be reached and editing in the page goes on.

### 6. Packaging

- **Off means absent.** `glot: { enabled }` decides at build time. When it is false the module's `setup` returns before adding any plugin, template, asset or runtime config, so a production build carries zero Glot bytes. Proved by building the playground both ways and searching `.output` for Glot strings.
- **On means dormant.** The enabled build adds one small client plugin. It reads `localStorage` and the URL; for everyone else it does nothing more. For a member it installs the key log and imports the widget chunk (Vue components, the compiled stylesheet, the oRPC client) on demand.
- **One build per environment.** An app that promotes one image from UAT to production must build twice, with and without Glot. A runtime switch cannot remove code that is already in the bundle.
- **Nuxt 3 and 4.** Only `@nuxt/kit` APIs that exist since Nuxt 3.13 (`defineNuxtModule`, `addPlugin`, `addTemplate`, `nitro.publicAssets`); the plugin runs on the client only and is SSR-safe because it touches nothing until mounted.
- **Options.** `enabled`, `url` (the Glot server), `project` (the repository, unique per Glot server).

## Open

- Nuxt 3 is covered by the APIs used, not yet by a running Nuxt 3 playground.
- The layer manifest (which source wins a key, pre-spec §4) is not built: a dotted key that two sources hold is offered as a choice.
- Screenshots of the page for reviewers (v1.1) and the fits check against the real line width are left for later slices.
